# Architecture

Everything below was read from the code. Where a behaviour depends on tvOS itself and has not been observed on a device, it says so.

## 1. Modules and layering

Two build products:

- **`StorySoundsCore`**: a local Swift package (`Package.swift`, no dependencies, resources processed from `Sources/StorySoundsCore/Resources`). It has no SwiftUI. Everything testable lives here.
- **`StorySounds`**: the SwiftUI app target (`App/`), which depends on the package. There are also two test targets: `StorySoundsCoreTests` (XCTest unit tests) and `StorySoundsUITests` (XCUIRemote).

```
App (SwiftUI)                 Child/  Parent/  Shared/ (AppEnvironment, Theme, components)
  |                              |       |          |
  v                              v       v          v
StorySoundsCore    Models  <--  Engine  <-- (planner, generator, mastery, progression)
                     ^            ^
                     |            +-- Parent (gate, report)  uses Models only
                     +-- Audio (library, planner, controller, AVFoundation adapters)
                     +-- Persistence (stores, compactor, coordinator, backup, sanitiser)
```

| Layer | Folder | Responsibility |
|---|---|---|
| Curriculum data | `Models/Curriculum.swift`, `Resources/*.json` | Codable model of units, words, tricky words, sentences, stories, word requirements and the audio manifest. `Curriculum.loadBundled()` throws rather than returning partial content |
| Learner model | `Models/Learner.swift` | `Attempt`, `SkillState`, `LearnerProfile`, `LearnerSettings`, `MasterySettings`, `SessionSummary`, `Activity` and payload types |
| Progression engine | `Engine/` | `CurriculumIndex` (lookups, decodability), `ActivityGenerator`, `Mastery` and `Scheduler`, `Progression`, `SessionPlanner` and `Baseline`, `Feedback`, `SeededRNG`. Pure functions: callers pass `now` and a seed. See [MASTERY_AND_PROGRESSION.md](MASTERY_AND_PROGRESSION.md) |
| Audio | `Audio/` | `AudioLibrary` (id to file), `PlaybackPlanner` (pure decision), `AudioPlaybackController`, `AVAudioPlayerBackend`, `AVSpeechFallback`, `AVAudioSessionObserver`. AVFoundation is isolated behind the `AudioBackend` and `SpeechFallback` protocols so tests use fakes |
| Persistence | `Persistence/` | `KeyValueStoring` (UserDefaults, iCloud KVS, in-memory), `KeyValueLearnerStore`, `SnapshotCompactor`, `PersistenceCoordinator`, `SnapshotEnvelope` and `Migrator`, `BackupCodec`, `ICloudKeyValueBackup`, `BackupRestoration`, `SnapshotSanitizer`, `DataDeletionService` |
| Parent logic | `Parent/` | `ParentGateSession` (hold, adult questions, lockout), `ParentReport` |
| UI | `App/` | SwiftUI views. `AppEnvironment` is the single integration object (`@MainActor ObservableObject`): it owns the curriculum, index, audio, store and coordinator, and both the child and parent UIs read and write learner state only through it |

Known coupling: `Mastery` reads two constants from `SnapshotCompactor` (history caps), and `Mastery.update` calls `Progression.meetsSoftPass`. `AppEnvironment` is large (storage, audio and navigation in one object) and every view depends on it; `StoryButton` reads it only to learn whether Gentle mode is on.

Navigation is a `Route` enum on `AppEnvironment`: `onboarding`, `home`, `baseline`, `session`, `summary(SessionSummary)`, `parent`. `RouterView` switches on it with opacity transitions. The only way from the child area to the parent area is Home, "Grown-ups", then `ParentGateView`.

## 2. Data model

### 2.1 Curriculum JSON (`curriculum.json`, schema version 1, content version 0.1.0)

Generated by `curriculum-tools` (authoring schema in `curriculum-tools/src/domain/schema.ts`, Swift model in `Models/Curriculum.swift`). Current contents: 99 units (55 Reception: 37 phase 2, 14 phase 3, 4 phase 4; 44 Year 1 phase 5), 1,284 words, 65 tricky words, 306 sentences, 18 stories, 380 word-requirement entries. Every unit has `source: "inferred"`.

Top level: `schemaVersion`, `contentVersion`, `units`, `words`, `trickyWords`, `sentences`, `stories`.

**Unit (`GraphemeUnit`)**: `id` (`g-s`, `g-oo-short`, `p4-cvcc`...), `order` (global teaching order, unique, ascending), `phase` (2 to 5), `stage` (`reception` or `year1`), `term` (text), `phoneme` (ASCII label such as `/s/`), `graphemes`, `kind` (`single`, `digraph`, `trigraph`, `split`, `alternative`), `audioId` (`ph-<unit id>`, or the instruction clip `i-blend` for units with no sound of their own), `pronunciation` (adult guidance), `prerequisites` (unit ids), `exampleWords`, `trickyWords` (introduced with the unit), `misconceptions` (`confusedWith`, `guidance`), `source`, `citation` (optional text; never shown in the UI), and `reviewIntervalsDays` (optional; decoded but never read by the app).

**Word**: `text`, `graphemes` (segmentation), `emoji`, `pictureLabel`, `concrete` (whether it can be pictured), and three optional fields:
- `homophones`: same sound, different spelling (sea/see). Never offered together as answer and distractor.
- `sameMeaningAs`: would also fit the picture or sentence (cup/mug). Same rule.
- `accentNote` (boolean): the vowel depends on accent (bath, path, fast...). Present in the JSON and the authoring schema (14 words) but the Swift `Word` does not decode it, so the app ignores it today; the authoring tools keep these words out of unit example words.

Swift decodes `homophones` and `sameMeaningAs` leniently (a list or a single string; anything else becomes nil rather than failing the load). `CurriculumIndex` also holds about 80 built-in homophone groups used in addition to the data.

**Tricky word**: `text`, `introducedAtOrder` (a unit order), `trickyPart`, `decodablePartsKnown` (not read by the engine).

**Sentence**: `id`, `text`, `tokens` (each `{kind:"word", text, graphemes}` or `{kind:"tricky", text}`), `unlockedByOrder`. Sentences carry no emoji in the current data; a sentence's picture comes from the story page that shows only that sentence.

**Story**: `id`, `title`, `pages` (each `sentenceIds`, `emoji`, `pictureLabel`).

### 2.2 Decodability and `word-requirements.json`

A word unlocks at the highest `order` among the units that first teach each of its graphemes (`CurriculumIndex.computeUnlock`). Knowing the letters is not always enough, so `word-requirements.json` maps a word (lower case) to extra unit ids that must also be taught. Examples: `book` needs `g-oo-short`, `this` needs `g-th-voiced`, `gene` needs `g-g-j`. The unlock order is then the maximum over graphemes and required units. A grapheme in no unit, or an unknown required unit, gives `Int.max`: never available. Sentences unlock at the maximum of their tokens (tricky words at `introducedAtOrder`) and their stored `unlockedByOrder`; stories at the maximum of their sentences.

The three consolidation units (`p4-cvcc`, `p4-ccvc`, `p4-long`) list practice clusters, not new graphemes, so they do not enter the taught set. `p4-suffix` genuinely adds `ed`.

Word requirements also tell the audio layer which sound a grapheme makes in a word: `CurriculumIndex.audioId(forGrapheme:inWord:)` picks the latest required unit that teaches the grapheme (so `o` in `cold` plays the long-o recording), else the first unit that teaches it.

### 2.3 Split-digraph convention

A split digraph is written `a_e`, `i_e`, `o_e`, `u_e`, `e_e` and sits at the vowel's position. The silent `e` is not its own token; it is emitted right after the next token. `cake` is `["c","a_e","k"]`, `slide` is `["s","l","i_e","d"]`, `age` is `["a_e","g"]`. Exactly one following token must exist. `GraphemeText.join` (Swift) and `joinGraphemes` (TypeScript) implement this and return nil for a dangling or overlapping split digraph. The UI shows the grapheme with an en dash (`a-e`) and VoiceOver reads it as "a e".

### 2.4 Audio manifest (`audio-manifest.json`)

`{version, statement, entries}`. Each entry: `id`, `kind` (`phoneme`, `word`, `instruction`, `sfx`), `label` (caption text), `file` (nullable), `slowFile` (optional), `status` (`placeholder`, `recorded`, `verified`), `note`. Ids: `ph-<unit id>`, `w-<lower-case text>` (always derive through `AudioIds.word`, never concatenate), `i-...`, `sfx-...`. Currently 1,483 entries (95 phoneme, 1,364 word, 18 instruction, 6 sfx), all `status: placeholder` with `file: null`. Resolution order in `AudioLibrary.resolve`: a bundled file when the entry is `recorded` or `verified` and the file exists in the bundle; else a parent recording from a `RecordingStore`; else placeholder. There is no real `RecordingStore` (see [CONTENT_AND_LICENSING.md](CONTENT_AND_LICENSING.md)).

Speech policy (`SpeechPolicy`, enforced in `PlaybackPlanner`, in `AudioPlaybackController.play` and in `AVSpeechFallback.speak`): text-to-speech is allowed only for words and instructions. Phonemes and sound effects are never synthesised; a missing phoneme becomes an on-screen caption.

### 2.5 Learner data (`LearnerSnapshot`)

`profile` (random UUID `id`, preset `nickname`, `createdAt`, `baselineDone`, `baselinePlacementOrder`, `settings`, `stickers`, `overrides`, versions), `skills` (`SkillState` per unit and track), `confusions`, `sessions`, `attempts`. Tracks are `recognise`, `blend`, `segment`, `read`. A `SkillState` holds the mastery evidence (score, independent attempt count, sessions and days seen, activity types seen, last eight results, status, review stage and date, struggle streak, `secureAt`, `softPassedAt`). Details in [MASTERY_AND_PROGRESSION.md](MASTERY_AND_PROGRESSION.md).

## 3. Persistence on tvOS

### 3.1 Constraints

tvOS apps have no durable Documents directory. Caches and tmp can be purged by the system, and there is no file sharing. The only durable app-writable local store is `UserDefaults`, which Apple documents as limited to about 500 KB. The design therefore keeps all learner data in `UserDefaults` under a small budget. iCloud key-value storage (about 1 MB in total) is the only off-device route and is opt-in.

### 3.2 Layout and keys

Every key the app writes starts with `storysounds.` so that deletion can sweep by prefix.

| Key | Content |
|---|---|
| `storysounds.learner.<scope>.snap.<profile>.<generation>` | A `SnapshotEnvelope` (`schemaVersion`, `savedAt`, `snapshot`) as JSON |
| `storysounds.learner.<scope>.ptr.<profile>` | The current generation number for that profile |
| `storysounds.learner.<scope>.active` | Core's active-profile pointer (set by "Start fresh" only; see below) |
| `storysounds.ui.activeProfile` | The app's active-profile pointer (set on every normal launch) |
| `storysounds.privacy.<scope>` | `PrivacySettings`: `iCloudBackupEnabled` (default false), `lastBackupAt` |
| `storysounds.parentgate.lockout` | Parent-gate lockout state |
| `storysounds.ui.soundOn` | Bool |
| `storysounds.backup.v1` (iCloud KVS only) | The compressed backup payload |

`<scope>` is `_` today (see section 3.7).

### 3.3 Budget, compaction

`SnapshotCompactor.defaultBudget` is 150,000 bytes for one snapshot, and the store refuses anything over `KeyValueLearnerStore.defaultMaxBytes` (200,000). Because a save briefly holds two generations, peak use is about 2x one snapshot; the code comments state the intent to stay under about 400 KB. This was not measured on a device. The compactor, applied before every save by `PersistenceCoordinator`:

1. trims per-skill history (20 session ids, 45 day keys, 8 recent results);
2. keeps the newest 300 attempts, folding dropped wrong answers into `ConfusionRecord`s only when no record for that expected/chosen pair exists;
3. keeps the newest 60 sessions and 80 confusions;
4. if still over budget, halves attempts, then sessions, then confusions, then the per-skill history.

Profile, settings, stickers, overrides and skill states are never dropped. Session ids are short (`plan-<time base 36>-<seed base 36>`, about 15 characters) to protect the budget.

### 3.4 Two-generation save

`KeyValueLearnerStore.save`: encode, check the size cap, write a new generation key, read it back, flip the pointer, read it back, then delete every other generation of that profile (so generations orphaned by a crash are reclaimed on the next save). A failure before the flip leaves the previous generation intact and restores the pointer. Loading never trusts a pointer whose data fails to decode (`StorageError.corrupt`); a snapshot written by a newer schema throws `.newerSchema`. Limit, stated in the code: the read-back goes through `UserDefaults`' in-process cache, so it proves the write was accepted, not that it reached disk. Durability is only proven by reading the data after a relaunch, which the persistence UI tests do in the simulator.

`PersistenceCoordinator` debounces saves by 2 seconds on a serial queue and keeps the pending snapshot if a save fails. `flushNow()` saves synchronously.

### 3.5 Active profile

The app does not yet use Core's `activeProfileId()` for normal launches. It uses its own `ProfileSelection` (key `storysounds.ui.activeProfile`; a `TODO(core)` in `AppEnvironment.swift` marks it for removal). At launch: read the profile ids; if the active id loads, use it; if the active profile exists but cannot be read, stop and show the "saved adventure cannot be opened" screen (no new profile is created, nothing is deleted); otherwise choose the most recent valid profile (newest attempt, session or creation date); if none exists, onboarding. A grown-up can choose "Start fresh" behind a two-step confirm: a new profile is created and made active, and the unreadable data stays on disk, set aside. A restore from iCloud switches to the restored profile.

### 3.6 Backup and no file export

`ICloudKeyValueBackup` writes one payload (format version, date, compacted snapshots; LZFSE-compressed, "SSB" header, 700,000 byte cap) to `NSUbiquitousKeyValueStore`, only after the parent opts in, and only from the "Back up now" button. It reads the copy back and reports failure if it is missing. Restore validates the payload and the schema first, sanitises every snapshot (`SnapshotSanitizer`: unknown units dropped, counts, dates, text and settings clamped), saves each profile atomically with rollback, then makes the most recently active restored profile active.

There is deliberately no file export or import: tvOS has no file sharing and no durable Documents directory, so a file route would not be technically appropriate. The on-screen progress summary and the opt-in iCloud backup are the only ways to keep a record.

### 3.7 Household users (not implemented)

`AppEnvironment.currentUserScope()` returns nil and TVServices is not imported, so there is one shared household profile. The `userScope` parameter exists in the stores and only changes the key prefix; adopting `TVUserManager` would mean returning its identifier from that one function. This is a hook, not a feature, and has not been tried.

## 4. Lifecycle

- **Launch**: `EnvironmentHost` builds `AppEnvironment` (load curriculum and manifest; choose a profile; build audio). A curriculum load failure or an unreadable profile sets `loadFailure`; `RootView` then shows `LoadErrorView` (Try again, and for unreadable progress only, Start fresh) and saving is disabled while it is showing.
- **Scene phase** (`RootView`): `.inactive` (Siri, system alerts) flushes the pending save; `.background` flushes and stops narration; `.active` does nothing. The parent area re-locks whenever the phase is not active.
- **Session**: `SessionModel.start` plans the whole session up front; each answered activity writes attempts through `AppEnvironment.recordAttempt`; `finish` writes the summary and stickers and flushes.
- **Audio**: `AppEnvironment.playSequence` stops everything, then plays ids one after another, waiting for the controller's completion signal when a clip or placeholder speech is playing, or an estimated reading time when only a caption is shown. A screen cancels only its own prompt (`cancelSequence(token:)`).
- **Time**: `AppEnvironment.now` is `Date()` plus any `-uitest-day-offset`.

## 5. Launch arguments (DEBUG only)

`LaunchOptions.init(arguments:)` ignores its input in Release builds (`#if DEBUG` around the whole parsing), as does the gate's hold-skip flag and `DebugHooks`. CI builds Debug, so the UI tests work. Not covered by a Release-build test.

| Argument | Effect |
|---|---|
| `-uitest-reset` | Wipe all stored data at launch |
| `-uitest-inmemory` | In-memory stores; nothing written to disk |
| `-uitest-reduce-motion` | Behave as if Gentle mode were on |
| `-uitest-no-audio` | Silent backend and no text-to-speech (captions only) |
| `-uitest-fast-review` | Treat "now" as two days later |
| `-uitest-day-offset N` | Treat "now" as N days later |
| `-uitest-session-minutes N` | Override the session length |
| `-uitest-seed N` | Fixed session seed |
| `-uitest-force-load-error` | Show the unreadable-progress screen (Retry clears the flag) |
| `-uitest-first-choice-wrong` | Put the correct choice last so the "do it together" path is reached deterministically |
| `-uitest-parent-gate-pass` | Skip the 3-second hold; the adult questions are still required |

## 6. Focus and navigation model

Input is the Siri Remote only: directional focus movement, Select, Menu and Play/Pause. There is no text field, drag, hover or touch-only gesture; the one gesture is the gate's press-and-hold.

- **Focus**: SwiftUI `@FocusState` with `.defaultFocus`, `.focusSection()` on rows, grids and pager bars, and one delayed assignment per appearance to set the initial focus. Every button uses `FocusCardStyle` (or `ParentRowStyle` in the grown-ups' area): scale, an 8 pt white outline and a shadow. Gentle mode or Reduce Motion removes the scale and animation but keeps the outline. Disabled buttons are not focusable, so the code hands focus on explicitly when a focused control becomes disabled (for example the story "Back a page" at page 0). Focus is restored to the control that opened an overlay or sub-screen.
- **Menu**: on root screens (onboarding, home, the load-error main panel) there is no handler, so the system takes the app to the Apple TV Home Screen. On nested screens it goes up one level (sticker book, baseline intro and outro, summary, every parent screen). Inside an activity it opens "Take a break?" (baseline: "Skip the games?") with "Keep playing" focused; pressing Menu again keeps playing. Confirmations in the parent area default to Cancel and Menu cancels.
- **Play/Pause**: replays the spoken prompt inside activities; does nothing elsewhere.
- **Child controls**: minimum target 120 pt (scaled with Dynamic Type), choice cards 170 pt high or more.
- **Grown-ups' area**: paged screens with Previous / Next / Back instead of scrolling; steppers whose buttons are never disabled (so focus never jumps).

The focus model is verified only in the simulator by the UI tests (home always has focus, Menu returns to the opener, the confirm screen defaults to Cancel, and so on). It is not verified on a real Apple TV.
